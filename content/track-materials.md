# 🗃 발표 재료 창고

> 키노트 장표·피치덱·시각화 산출물을 만들 때 꺼내 쓸 재료를 **단계가 진행될 때마다 누적**하는 곳. 문장은 다듬지 말고 원석 그대로 쌓는다. (규칙: 새 결정·새 숫자·새 인용이 생기면 즉시 여기에 한 줄 추가)

## A. 서사 문장 (피치 카피 원석)

- **핵심 메시지: "관측할 수 있으면 줄일 수 있다."** — 첫 버전 43배 낭비 → Trace로 해부 → 17배 절감, 전부 리플레이됨 (시각화 30 + 효율 30을 인과로 묶는 한 줄)
- **"손에 쥘 수 있는 모델로 어디까지 갈 수 있는가? — 낭비를 볼 수 있을 만큼 멀리, 그만큼 싸게."** (오프닝, 키노트 질문 화답)
- **"손에 쥘 수 있는 모델로 어디까지 갈 수 있는가? — 한 그릇이면 충분합니다."** (오프닝 대안)
- "재료 하나하나는 한 끼가 못 되지만, 비비면 완성됩니다." (아키텍처 한 문장)
- **"비용은 로스터가 아니라 홉이 결정한다."** (설계 원칙 — 등록 ≠ 출전)
- "로스터는 넓게, 경로는 짧게."
- **"새로운 정보를 주지 못하는 측정에 가장 비싼 시간을 쓰지 않는다."** (EXAONE coding 생략 명분 — 엔지니어링 판단력 어필용)
- "캡 관리가 곧 정확도다." (Qwen coding 35% 붕괴에서 도출)
- "우리는 X% 정확도를 정답 1개당 평균 Y토큰으로 달성했고, 그 판단 과정 전부를 되감아 볼 수 있습니다." (클로징 — 수치 확정 후 채움)
- "지능은 전기처럼 흐른다 — 저전력 한국산 NPU 위에서." (비전, Lablup 문장 인용 연결)
- **"API 1회분 비용으로 θ 11개를 전부 평가했다."** (θ 스윕 — 실험 설계 어필: 전 문항에 두 모델을 각 1회 호출·기록해두면, 어떤 임계값이든 오프라인 재계산 가능)
- "임계값은 감으로 정하지 않는다 — 정확도×토큰 곡선에서 읽는다." (θ 스윕)
- "모델의 자기 확신은 검증 대상이지 신뢰 대상이 아니다." (확신 캘리브레이션 — 스모크에서 전 문항 conf 9 과신 관찰 → 게이트 신호 자체를 실험으로 판정)

## B. 숫자 증거 (장표용 데이터)

**베이스라인 최종 매트릭스** (visible, max_tokens 4096, 정확도/출력tok/문항):

| 모델 | generic | math | coding(LCB) |
| --- | --- | --- | --- |
| gpt-oss-120b | 60% / 572 | **100% / 740** | **85% / 2,036** |
| K-EXAONE-236B | 50% / 2,852 | 86.7% / 2,617 | 생략 |
| Qwen3-32B | **65% / 1,202** | 86.7% / 2,792 | 35% / 3,237 |

- **43× → 2.6×** (실행 단계) / **≈5.7× → ≈3.3×** (플래너 포함 추정): 같은 문항, 같은 스쿼드 — 첫 완주 26,808tok/60s → v3.7b 1,611tok/17s (÷17). **메시지의 증거 숫자** — 플래너 비용까지 합쳐 말할 것(정직)
- **전수 측정 정정**: generic 베이스라인 60%(20문항)는 표본 불운, 전수 140은 79.1% → 최신 80.9%(+1.8%p, 토큰 −16%) · math 79.8 → 82.6%(−21%) · LCB 75 → 88.9%(−15%). "정확도는 지키고 토큰을 줄였다"가 정확한 문장
- **28회 → 2회**: 태스크당 모델 호출 (루프 규약 역공학으로 공회전 제거)
- **33배**: 같은 쉬운 문제(17×23)에 gpt-oss 48tok/0.6초 vs Qwen3 1,596tok/24초 — "라우팅이 왜 필요한가" 장표의 핵심 숫자
- **97%**: 리더보드 공식 경고 — 한 평가 모델은 출력 예산의 97%를 사고 토큰에 소비
- **16.5K tok**: SWE-bench 문항 하나의 입력 크기 실측(66KB) — 컨텍스트 전략 근거
- **컨텍스트 한도**: gpt-oss 128K / EXAONE 48K / Qwen 40K (입력+출력 합산, 공식)
- **히든 세트 분포**: generic 448~698 / coding 140~240 / math 60~66 — "수학 대회가 아니라 상식 대회" 장표
- **배점**: 벤치마크 40 / 시각화 30 / 토큰효율 30 — "60점은 엔지니어링 바깥에 있다"
- **캐시 실증**: 86토큰 중 68토큰 적중 (prefix cache 동작 확인)
- **confgate 스윕(n=140 최종)**: gpt-oss 단독 **78.6% @ 511tok/문항** vs Qwen 66.9% / 게이트 θ=8이면 75.0%로 하락+토큰 1.6배, θ=10이면 67.9% / 교정 4건 vs 가로챔 20건(conf 10에서도 1건) — "2차 의견 기각" 장표의 근거 숫자
- **캘리브레이션 곡선**: 단조 감소 유지(최종 n=140), 단 conf 10에서도 가로챔 1건 — 완벽하진 않음 — The Receipt/Insightfulness 재료
- **프롬프트 효과**: 같은 모델·같은 문제군에서 프롬프트 구조 변경만으로 generic 60%→76.8%
- 과금 구조: Check 무료 무제한 / Test run 1/5 / Submission 전액·전 제출 합산 / 큐 대기1·실행1

## E. 데모 장면 후보 (시각화 재료)

1. **Before vs After 리플레이 경주** — 같은 문항·같은 스쿼드의 run-001(28호출·26.8K tok·60s)과 run-002(2호출·1.5K tok·7.9s)를 나란히 재생. 왼쪽이 공회전하는 동안 오른쪽은 8초에 끝남 — **핵심 메시지의 실증 장면** (데이터 둘 다 확보됨)
1-b. Baseline vs BIBIMBAP 경주 — 단독 모델 617tok vs 스쿼드 1,564tok (2.5×)
2. 그릇(방사형) 리플레이 — 재료가 섞이듯 메시지가 흐르고 문항마다 비빔밥 한 그릇 완성
3. give-up 순간 — Verifier가 "확정" 판정하며 주황불, 아낀 토큰 카운터 상승
4. The Receipt — 정답 1개당 토큰 영수증, 캐시 적중률 게이지
5. 관람객 인터랙션 — 스크러버를 심사위원 손에 쥐여주기 (데모 엑스포 운영)
6. 33배 차이 장면 — 같은 쉬운 문제를 두 모델에 던지는 10초 클립
7. **θ 스윕 곡선** — x축 θ(0~10), y축 정확도·문항당 토큰의 2축 라인차트: "우리가 임계값을 고른 지점"에 마커. The Receipt 화면과 피치 6번 장표(토큰 전략)에 삽입. *(confgate 결과로 실데이터 채움)*
