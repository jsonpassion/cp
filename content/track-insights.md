## 📊 베이스라인 최종 매트릭스 (visible practice set, max_tokens 4096, 단순 프롬프트)

**정확도 / 문항당 출력 토큰** — generic 20 · math 15 · LCB 20문항:

| 모델 (ctx) | generic | math | coding(LCB) | 응답속도 |
| --- | --- | --- | --- | --- |
| **gpt-oss-120b** (128K) | 60% / 572 | **100% / 740** 🥇 | **85% / 2,036** 🥇 | 빠름 (쉬운 문제 0.6초) |

\* EXAONE coding 생략 사유: 측정 2트랙 전패(정확도·토큰·속도) + FuriosaAI 공식 배치 비권고 → **새 정보를 주지 못하는 측정에 가장 비싼 30분을 쓰지 않음** (감시 스크립트로 자동 skip).

### 매트릭스가 말해주는 것 4가지

1. **math·coding은 gpt-oss 단독 확정** — math 만점(740tok), coding 85%. 2위 모델을 검증자로 붙일 이유조차 없음.
2. **Qwen coding 35%는 "토큰 캡" 경고의 실증** — 리더보드 공지("reasoning 스쿼드에 캡이 10배 가혹")가 그대로 재현됨: 4096 캡 안에서 사고 토큰을 다 쓰고 코드를 못 뱉음. **캡 관리가 정확도 그 자체**라는 증거.
3. **generic 하이브리드 기각 → 전 트랙 gpt-oss 단독 확정** — confgate(n=140 최종): gpt-oss **78.6%** vs Qwen 66.9%. 베이스라인 20문항의 "Qwen 우위(65>60)"는 소표본 노이즈였고, 약한 모델의 2차 의견은 교정(4건)보다 가로챔(20건)이 많아 **모든 θ에서 순손실**. θ=0 확정, Adjudicator 로스터 제거(9→8종). 배포 비용 문항당 **511토큰**.
4. **확신 자기보고는 정직하게 캘리브레이션됨** — conf 10→100%(24/24), 9→79%, 8→65%, ≤3→25%로 단조 감소. 게이트 신호로는 갈 곳이 없어 폐기하지만, **시각화(캘리브레이션 곡선)와 give-up 신호로 재활용**.
5. **부수 발견: 프롬프트 구조가 정확도를 올림** — "3문장 추론 + Confidence 커밋" 요구만으로 generic 60%→**78.6%** (n=140, 문항당 511토큰). 구조화된 짧은 추론 > 맨 답변 요구.


## 🔥 첫 완주 런의 비용 해부 (8/22 오후) — 43배 낭비의 정체

같은 문항(math-visible-0001)을 단독 gpt-oss는 **617토큰·5초**에, BIBIMBAP 스쿼드는 **26,808토큰·60초**에 풀었다(둘 다 정답). 낭비는 두 층의 곱:

| 층 | 관찰 | 배수 |
| --- | --- | --- |
| 플래너 중복 | 동일 SOLVE 태스크 3개 | ×3 |
| **에이전트 루프 공회전** | 태스크당 11·6·11회 호출, 호출당 출력 평균 84토큰(풀이 본문은 마지막 1회 315토큰뿐), 입력은 487→1,277로 매회 재전송·누적 | ×9 |
| (미계상) 플래너 토큰 | 로컬 로그에 계획 단계 토큰 없음 — 실제 비용은 더 큼 | ? |

→ **레버 두 개 (16시, 앱 바이너리 분석으로 규약 확정)**: 루프 종료 = *"provide your response directly"*(도구 호출 없는 본문 응답), 빈 본문 = *"continuing..."*(재시도). ① 플래너는 `create_task` 도구 호출 루프 → "1회 호출 후 본문 'PLAN READY'"로 종료 강제(÷3) ② 솔버는 "본문을 비우지 말 것" 프로토콜로 1~2회 호출(÷5~9). 로컬 루프 상한은 `tools.maxToolLoops: 10`. 둘 다 풀면 문항당 1,000~2,000토큰대 = 단독의 2~3배 수준. 모든 팀이 같은 구조를 쓰므로 **이걸 푼 팀이 효율 30점을 가져간다.**

## 🎯 판을 결정하는 인사이트 10

1. **배점 40/30/30** — 벤치마크는 순위제. 정확도만 파는 팀은 최대 40점, 시각화·효율은 설계만 잘하면 따라오는 60점.
2. **히든 세트는 generic이 지배** (448~698문항 vs math 60~66) — "수학 스쿼드"를 만들면 진다. **MMLU-Pro 정확도가 실점수의 중심.**
3. **평가 중 도구·MCP·외부코드 원천 차단** (공식 확답) — 스쿼드의 무기는 역할·프롬프트·모델 배정뿐. 코드 실행 검증은 개발 단계 전용.
4. **에이전트 수는 제약이 아니다 (≤50)** — 비용은 문항당 **홉 수**가 결정. 전담 스페셜리스트 로스터(8~9) + 문항당 2~3홉이 정답.
5. **컨텍스트 = 입력+출력 합산** (gpt-oss 128K / EXAONE 48K / Qwen 40K). SWE-bench 입력 실측 ~16.5K tok → **대형 입력은 gpt-oss만 안전**, 소형 모델엔 청킹 에이전트로 요약 전달 (FuriosaAI 공식 권장).
6. **토큰 캡은 reasoning 스쿼드에 ~10배 가혹** (리더보드 공식 경고: 한 모델은 출력의 97%가 사고 토큰). 쉬운 문제에 reasoning을 쓰면 캡으로 자멸.
7. **prefix cache 실동작 확인** — 고정 prefix 앞 + `{{TASK}}` 맨 뒤 구조가 공식 할인 경로.
8. **제출은 전액 과금·전 제출 합산, Check는 무료 무제한** — 시행착오는 dev key(계상 0)와 Check에서 끝내고, Submission은 수렴 후 최소 횟수만. 큐: 대기 1·실행 1.
9. **math는 `run_repeats: 2`** — 재현성 없는 정답은 반값. 온도 낮추고 형식 고정.
10. **형식 오류 = 0점** — REQUIRED OUTPUT 준수를 지키는 Format-Warden 홉이 싸고 확실한 보험. published requests에서 실제 요청 포맷 확인 가능.
