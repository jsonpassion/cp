## 7. SWE-bench 전멸의 원인은 풀이가 아니라 **패치 형식** — 채점기 허용 범위를 실측했다 (8/23 09시)

- 보드의 코딩 21.1%는 **8/38 = LiveCodeBench 문항만** 맞은 값(1위도 같은 21.1%). SWE ~30문항은 전원 0. 우리 출력을 보니 diff의 hunk 헤더가 숫자 없는 `@@`뿐 — `git apply`·GNU `patch` 모두 "패치 없음"으로 거부(연습 SWE 5/5). 채점기 = swebench_docker = SWE-bench 하네스(`git apply` → `git apply --reject` → `patch --batch --fuzz=5 -p1`).
- 로컬 실험(정상 파일에 변형 패치 적용): 시작 줄 S 오차 → **허용**(오프셋 탐색) · 컨텍스트 1줄 → 허용 · 카운트가 **대칭으로 작음** → 둘 다 허용 · 대칭으로 큼 → patch만 허용 · **+/− 줄 수 비대칭 오산 → 둘 다 치명** · 컨텍스트 0줄 → git 거부.
- 처방 = 패치 계약을 페르소나 SWE 불릿과 coding one-shot에 명시: 경로 정확, **3+3 컨텍스트**, `@@ -S,L +S,M @@`에서 **L = 6 + 삭제, M = 6 + 추가**(세어서 쓰기), 컨텍스트·삭제 줄은 발췌 원문 그대로. 결과(연습 SWE 8문항): 숫자 헤더 0/8 → 8/8, 적용 성공 1~2/8(남은 실패는 ±1 오산), LCB 20문항 회귀 **20/20**. 1+1 컨텍스트 변형은 모델이 다시 빈 `@@`로 회귀(템플릿 혼동) → 폐기. 모델은 줄 수를 못 세므로 hunk를 작게 유지하는 것이 핵심.
